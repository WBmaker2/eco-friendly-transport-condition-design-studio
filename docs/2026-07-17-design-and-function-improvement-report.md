# 친환경 수송 조건 설계소 기능·디자인 개선 기록

- 분석·개선일: 2026-07-17
- 대상: 친환경 수송 조건 설계소 MVP
- 검토 범위: 첫 화면, 임무 선택, 조건 확인, 첫 설계, 시험, 재설계, 결과 비교, 모바일·태블릿·데스크톱 반응형

## 1. 분석 목표

초등학생이 별도 설명 없이도 다음 행동을 찾고, 작은 화면에서도 편하게 누르며, 실수했을 때 이전 단계로 돌아가 설계를 고칠 수 있는지 확인한다. 시각적으로는 학습 흐름의 우선순위가 분명하고 장식보다 정보 이해를 돕는지 살펴본다.

## 2. 발견한 개선점

### FINDING-001 · 모바일 헤더와 첫 화면 위계

- 모바일에서 서비스 이름이 어색하게 두 줄로 갈라지고, `설계 원칙`, `교사용 안내`, `업데이트 내역` 버튼이 좁은 공간에 흩어진다.
- 유틸리티 버튼 높이가 약 36px로, 손가락으로 안정적으로 누르기에는 작다.
- 진행 단계와 첫 제목 사이의 여백이 커서 핵심 설명과 시작 버튼이 첫 화면 아래쪽으로 밀린다.
- 제목 굵기와 한글 줄바꿈 규칙이 약해 핵심 메시지가 또렷하게 읽히지 않는다.

개선 계획:

- 모바일 헤더를 브랜드 한 줄 + 3등분 도구 버튼 한 줄 구조로 정돈한다.
- 모든 주요 도구 버튼의 최소 높이를 44px로 높인다.
- 첫 화면의 수직 여백을 줄이고 제목 굵기·줄바꿈·한글 글꼴 체계를 정리한다.
- 안전 안내를 색 띠에 의존하지 않는 명확한 안내 상자로 바꾼다.

### FINDING-002 · 임무 선택의 스캔 효율

- 데스크톱에서는 5개 카드가 3열로 배치되어 둘째 줄에 빈 자리가 생긴다.
- 모바일에서는 각 카드가 지나치게 높아 5개 임무를 비교하려면 긴 스크롤이 필요하다.
- 카드 위계가 모든 화면에서 거의 같아 임무 번호, 제목, 설명을 빠르게 훑기 어렵다.

개선 계획:

- 넓은 화면에서는 5개 임무를 한 줄에 보여 비교를 쉽게 한다.
- 태블릿은 3열, 모바일은 번호와 설명을 나란히 둔 압축형 목록으로 전환한다.
- 선택·눌림·키보드 초점 상태를 명확하게 만든다.

### FINDING-003 · 중간 단계 되돌아가기

- 조건 확인 이후에는 이전 단계로 돌아가는 조작이 없어, 조건을 다시 읽거나 부품 선택을 고치려면 처음부터 다시 시작해야 한다.
- 이는 `조건 확인 → 첫 설계 → 시험 → 재설계 → 비교`라는 반복 학습의 흐름과 맞지 않는다.

개선 계획:

- 조건 확인부터 결과 비교까지 현재 단계에 맞는 `이전 단계` 버튼을 제공한다.
- 이전 단계로 돌아가도 이미 고른 임무와 부품은 유지하여, 학습자가 한 부분만 수정할 수 있게 한다.
- 단계 이동 규칙을 별도 모듈로 분리하고 회귀 테스트를 추가한다.

### FINDING-004 · 상호작용 피드백과 접근성

- 버튼에 hover와 focus 표현은 있으나 눌림 피드백이 약하다.
- 모션 감소 환경에서는 장식적 움직임을 최소화해야 한다.

개선 계획:

- 필요한 속성만 전환 효과를 적용하고, 눌렀을 때 짧은 위치 피드백을 준다.
- `prefers-reduced-motion` 환경에서는 기존과 같이 전환을 제거한다.

## 3. 구현 범위

1. 모바일 헤더, 타이포그래피, 첫 화면 간격, 안전 안내 상자 개선
2. 임무 카드의 데스크톱·태블릿·모바일 레이아웃 개선
3. 단계별 이전 이동 기능과 단위 테스트 추가

## 4. 구현 결과

### FINDING-001 완료

- 모바일 헤더를 브랜드와 3개 도구 버튼의 2단 구조로 재배치했다.
- 모든 도구 버튼을 최소 44px로 높이고, 375px 화면에서 한 줄에 안정적으로 배치했다.
- 첫 화면의 위쪽 여백을 줄이고 한글 시스템 글꼴, 제목 굵기, `word-break: keep-all`을 적용했다.
- 안전 문구를 `안전 안내` 제목이 있는 전체 테두리 안내 상자로 변경했다.

### FINDING-002 완료

- 데스크톱은 5열, 태블릿은 3열, 모바일은 1열 압축 목록으로 임무 카드를 재구성했다.
- 모바일 카드는 번호 영역과 설명 영역을 나눠 5개 임무를 빠르게 훑을 수 있게 했다.
- 카드 hover·focus·active 피드백을 정리했다.

### FINDING-003 완료

- `conditions → brief → … → compare → report` 흐름에 맞춘 이전 단계 규칙을 `app/transport/navigation.ts`로 분리했다.
- 조건 확인부터 비교서 완성까지 `이전 단계` 조작을 제공한다.
- 이전 단계로 돌아가도 임무, 부품 선택, 시험 결과가 유지된다.
- `tests/navigation.test.ts`에 이전 단계 규칙 회귀 테스트 2개를 추가했다.

### FINDING-004 완료

- 버튼에 배경색·테두리·그림자·위치만 제한적으로 전환되도록 설정했다.
- 눌림 피드백을 추가하고 모션 감소 설정에서는 모든 전환을 제거한다.
- 업데이트 내역에 `2026-07-17 · v0.2.0` 기록을 추가했다.

## 5. 검증 결과

### 자동 검증

- `npm test -- --run`: 3개 파일, 13개 테스트 통과
- `npm run lint`: 오류 없음
- `npm run build`: 프로덕션 빌드 성공
- 코드 크기: 모든 앱·테스트 코드 파일 500줄 미만

### 실제 브라우저 검증

- 화면 크기: 375×812 모바일, 768×1024 태블릿, 1280×720·1280×900 데스크톱
- 모바일 375px: 가로 넘침 없음
- 모바일 375px: 너비 또는 높이가 44px 미만인 버튼 0개
- 업데이트 내역: 열기, Escape 닫기, 실행 버튼으로 초점 복귀 확인
- 전체 학습 흐름: 임무 3 선택 → 조건 5개 확인 → 부품 4개 선택 → 첫 시험 → 목표 선택 → 부품 1개 변경 → 두 설계 비교 → 비교서 완성 성공
- 이전 단계: 완성 화면에서 비교 화면으로 정상 복귀하고 기존 결과 유지 확인
- 브라우저 콘솔 오류: 없음

## 6. 디자인 평가 요약

- 개선 전: 모바일 헤더와 첫 화면 위계가 약하고, 임무 카드 비교와 단계 복구가 불편한 상태
- 개선 후: 첫 행동, 단계 위치, 되돌아가기, 임무 비교가 화면 크기별로 명확한 상태
- 남은 수동 확인: 실제 학교 태블릿·저사양 기기에서의 스크롤 감각과 교실 투사 화면의 글자 크기는 수업 환경에서 한 번 더 확인하는 것을 권장한다.
