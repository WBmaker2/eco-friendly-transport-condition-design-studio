# 친환경 수송 조건 설계소 초등 3~4학년 사용자 경험 개선 설계

- 작성일: 2026-07-18
- 대상 버전: v0.3.0
- 대상 사용자: 초등 3~4학년 학생, 개인 또는 2인 모둠
- 개선 범위: 학생 화면의 문장 난이도, 부품 선택 흐름, 시험 결과 이해, 모바일 사용성

## 1. 목표

초등 3~4학년 학생이 교사의 추가 설명 없이도 다음 행동을 찾고, 어려운 기술 용어 때문에 멈추지 않으며, 한 번에 한 가지 선택에 집중해 첫 설계와 다시 만든 설계를 비교할 수 있게 한다.

기존 학습 원칙은 유지한다.

- 최고 점수나 정답 수레를 만들지 않는다.
- 한 부품이 모든 임무에 가장 좋다고 설명하지 않는다.
- 에너지원만 보고 친환경성을 판단하지 않는다.
- 실제 차량의 성능이나 안전을 보증하지 않는다.
- 첫 설계에서 한 부품군만 바꾸고 같은 조건으로 다시 시험한다.

## 2. 실사용 테스트 근거

2026-07-18에 375×812 모바일 화면에서 다음 흐름을 직접 완주했다.

`첫 화면 → 안내 실험 → 임무 3 → 조건 5개 확인 → 부품 4개 선택 → 첫 시험 → 다시 만들 목표 선택 → 이동부 변경 → 두 설계 비교`

### 발견한 주요 문제

1. `시제품`, `의뢰`, `재설계`, `적재부`, `접지`, `조향`, `제동`, `환경 프로필`처럼 3~4학년이 혼자 이해하기 어려운 말이 많다.
2. 모바일 설계 화면에 4개 부품군의 선택지 12개가 한꺼번에 이어져, 화면이 길고 현재 무엇을 골라야 하는지 알기 어렵다.
3. 모바일에서 아직 누를 수 없는 `첫 설계 시험하기` 버튼이 부품 선택지보다 먼저 보여, 다음 행동을 잘못 예상하게 한다.
4. 조건 카드가 이미 내용을 보여 주는데도 `모든 조건을 펼쳐야 부품 선반이 열립니다`라고 안내해 실제 조작과 문장이 맞지 않는다.
5. 결과 문장에 `보조을(를)`, `바퀴과`, `조향과(와)` 같은 조사 문제가 있다.
6. 비교 문장에 `있어요.을 더 생각해야 합니다`라는 문장 결합 오류가 있다.
7. `일부는 맞지만 살펴볼 점이 있어요`, `그대로 지킬 장점`, `실제 시험 결과에서 개선할 조건`은 문장이 길고 추상적이다.

## 3. 채택한 접근

문장만 바꾸는 방식 대신 `쉬운 말 + 한 단계씩 부품 고르기 + 짧은 결과 설명`을 함께 적용한다.

읽어주기 기능은 이번 버전에 넣지 않는다. 브라우저와 기기마다 음성 품질이 달라질 수 있고, 이번 목표는 화면을 읽고 직접 조작하는 기본 흐름을 먼저 단단하게 만드는 것이기 때문이다.

## 4. 학생용 쉬운 말 계약

학생 화면에서는 아래 표현을 우선 사용한다. 교사용 안내와 내부 데이터 이름은 필요한 경우 기존 전문 용어를 유지할 수 있다.

| 기존 표현 | 학생 화면 표현 | 사용 원칙 |
|---|---|---|
| 수송 의뢰 | 옮기기 할 일 | 처음 보는 학생도 행동을 예상할 수 있게 한다. |
| 시제품 | 시험용 수레 | 첫 등장부터 같은 말로 유지한다. |
| 재설계 | 다시 만들기 | 버튼과 진행 단계에 같은 표현을 쓴다. |
| 비교서 | 결과 비교 | 마지막 행동이 무엇인지 바로 알 수 있게 한다. |
| 구조·적재부 | 짐받이 | 필요하면 작은 글씨로 `구조·적재부`를 덧붙인다. |
| 이동부 | 바퀴 | 부품의 보이는 역할을 먼저 말한다. |
| 동력·에너지부 | 움직이는 힘 | 사람의 힘, 전동, 태양광 선택을 묶는 이름으로 쓴다. |
| 조향·제동부 | 방향·멈춤 | 두 기능을 일상 동사로 표현한다. |
| 도식 | 그림 | `수레 그림`으로 쓴다. |
| 접지 | 길에서 미끄러지지 않는 힘 | 결과 문장에서는 행동과 효과를 함께 쓴다. |
| 평탄 경로 | 평평한 길 | 임무와 부품 설명에서 같은 말을 쓴다. |
| 환경 프로필 | 에너지와 환경 생각 | 결과 묶음의 제목으로 쓴다. |
| 운행 중 | 움직일 때 | 짧은 제목으로 쓴다. |
| 개선할 조건 | 더 좋게 만들 것 | 학생이 선택 목적을 바로 이해하게 한다. |
| 그대로 지킬 장점 | 그대로 지킬 좋은 점 | `근거`라는 낱말 없이 선택하게 한다. |

### 문장 작성 규칙

- 한 문장은 원칙적으로 35자 안팎으로 쓴다.
- 한 문장에는 새 개념을 하나만 넣는다.
- `~을(를)`, `~과(와)` 같은 괄호 조사를 학생 문장에 사용하지 않는다.
- `확인합니다`, `보증하지 않습니다`보다 `살펴봐요`, `알려 주는 결과가 아니에요`처럼 짧은 말을 우선한다.
- 기술 용어가 꼭 필요하면 쉬운 말 뒤에 한 번만 괄호로 덧붙인다.
- 상태는 색과 함께 항상 글자로 표시한다.

## 5. 화면과 상호작용 설계

### 5.1 전체 진행 단계

상단 단계 이름을 다음처럼 바꾼다.

1. 할 일
2. 조건 보기
3. 수레 만들기
4. 첫 시험
5. 다시 만들기
6. 결과 비교

진행 단계의 내부 `Phase` 값은 바꾸지 않아 기존 평가 흐름과 이동 규칙을 보호한다.

### 5.2 첫 화면과 안내 실험

- 첫 제목은 `조건을 보고 시험용 수레를 만들어요`로 단순화한다.
- 보조 설명은 두 문장으로 나눈다.
- `안내 실험 시작`은 `먼저 연습하기`로, `안내 건너뛰기`는 `바로 시작하기`로 바꾼다.
- 안내 실험의 A·B 비교는 유지하되 `총점`, `재료`, `전동 보조`를 한 문장에 몰아넣지 않는다.

### 5.3 조건 확인

- 제목은 `조건 카드 5개를 눌러 보세요`로 바꾼다.
- 안내는 `카드를 한 번씩 누르면 다음으로 갈 수 있어요`로 바꾼다.
- 카드가 확인되면 체크 표시와 `확인했어요` 상태를 함께 보여 준다.
- 남은 개수는 `3개 더 눌러 보세요`처럼 행동 중심으로 말한다.

### 5.4 부품 선택

부품 선택은 한 화면에 한 부품군만 보여 주는 4단계 방식으로 바꾼다.

1. 짐받이
2. 바퀴
3. 움직이는 힘
4. 방향·멈춤

각 단계는 다음 요소를 가진다.

- `1/4` 형식의 현재 순서
- 쉬운 부품군 이름과 한 줄 역할 설명
- 해당 부품군의 선택지 3개
- 현재 선택한 부품의 도움과 생각할 점
- `이전 부품`과 `다음 부품` 버튼
- 마지막 단계의 `첫 설계 시험하기` 버튼

수레 그림과 지금까지 고른 부품 요약은 계속 보이게 한다. 모바일에서는 선택지가 먼저 나오고 수레 그림은 그 아래에 둔다. 시험 버튼은 네 번째 부품을 고르기 전에는 나타내지 않는다.

다시 만들기에서는 바꿀 부품군을 먼저 하나 고른 뒤, 그 부품군의 선택지 3개만 보여 준다. 다른 세 부품군은 `그대로 두는 부품` 목록으로 요약한다.

### 5.5 시험 결과

상태 문구를 다음처럼 바꾼다.

- `잘 맞아요`
- `조금 아쉬워요`
- `다시 골라 봐요`

각 결과 카드는 다음 구조를 사용한다.

1. 상태 + 조건 이름
2. `왜 그런가요?` 한 문장
3. `생각할 점` 한 문장

부품 이름을 두 개 나열할 때 조사를 붙이지 않는다.

예시:

> 짐받이: 낮고 넓은 적재판  
> 움직이는 힘: 충전식 전동 보조  
> 두 부품이 보통 무게의 짐을 옮기는 데 도움을 줘요.

`에너지·환경 프로필`은 `에너지와 환경 생각`으로 바꾸고, `움직일 때`, `에너지를 마련할 때`, `만들고 버릴 때` 세 묶음으로 나눈다.

### 5.6 다시 만들기와 결과 비교

- `무엇을 개선하고, 무엇을 지킬까요?`는 `더 좋게 만들 것과 지킬 것을 골라요`로 바꾼다.
- `개선할 조건 하나`는 `더 좋게 만들 것 1개`로 바꾼다.
- `그대로 지킬 장점 하나`는 `그대로 지킬 좋은 점 1개`로 바꾼다.
- 비교 화면은 `좋아진 점`, `그대로인 점`, `새로 생긴 어려움`의 세 묶음을 유지한다.
- 자동 비교 문장은 두 문장으로 나누고, 부품 부담 문장 끝의 마침표를 정리한 뒤 합친다.

예시:

> 바퀴를 `거친 길용 넓은 바퀴`로 바꿨어요. 그래서 `길의 상태`가 더 좋아졌어요.  
> 하지만 평평한 길에서는 힘이 더 들 수 있어요.

## 6. 코드 구조

한 파일이 500줄을 넘지 않도록 학생용 문구와 부품 선택 UI를 분리한다.

- `app/transport/student-copy.ts`: 진행 단계, 쉬운 상태 문구, 용어와 짧은 안내 문장
- `app/transport/BuildStep.tsx`: 4단계 첫 설계 부품 선택 UI
- `app/transport/RedesignStep.tsx`: 한 부품군만 바꾸는 다시 만들기 UI
- `app/transport/ResultBoard.tsx`: 쉬운 결과 카드와 에너지·환경 묶음
- `app/TransportApp.tsx`: 전체 단계 상태와 화면 전환만 담당
- `tests/student-copy.test.ts`: 금지 용어와 문장 결합 회귀 검사
- `tests/build-steps.test.ts`: 부품군 순서와 다음 단계 규칙 검사

평가 점수와 조건 계산은 `app/transport/evaluator.ts`의 기존 규칙을 유지한다. 이번 변경은 판정 수치를 바꾸지 않고 학생에게 보여 주는 문장과 조작 순서를 바꾼다.

## 7. 상태와 오류 처리

- 첫 설계에서 부품을 고르면 단계 이동 뒤에도 선택을 유지한다.
- 이전 부품 단계로 돌아가 선택을 바꿀 수 있다.
- 선택하지 않고 다음 단계로 가려 하면 버튼을 비활성화하고 `먼저 하나를 골라 주세요`를 보여 준다.
- 다시 만들기에서는 첫 설계와 정확히 한 부품군만 달라야 시험할 수 있다.
- 결과 문장에 값이 없으면 빈 문장을 만들지 않고 해당 결과 카드를 표시하지 않는다.
- 기존 `이전 단계` 이동은 그대로 유지한다.

## 8. 접근성 및 반응형

- 모든 버튼의 최소 높이와 너비는 44px 이상으로 유지한다.
- 선택지는 `fieldset`, `legend`, 라디오 입력을 유지한다.
- 현재 부품 단계는 글자와 `aria-current="step"`으로 알린다.
- 320px, 375px에서 가로 스크롤이 생기지 않아야 한다.
- 200% 확대에서도 핵심 버튼과 선택지가 겹치지 않아야 한다.
- 키보드만으로 조건 확인, 부품 선택, 시험, 다시 만들기, 비교까지 완료할 수 있어야 한다.
- 모션 감소 환경에서는 전환 효과를 제거한다.

## 9. 검증 설계

### 자동 검사

- 학생용 문구에 금지 용어가 직접 노출되지 않는지 검사한다.
- 상태 문구가 세 가지 쉬운 표현으로 매핑되는지 검사한다.
- 첫 설계 부품 단계가 4개 순서로 이동하는지 검사한다.
- 부품을 고르지 않으면 다음 단계로 갈 수 없는지 검사한다.
- 다시 만들기에서 한 부품군만 달라야 하는 기존 규칙을 유지한다.
- 비교 문장에 `(을)`, `(를)`, `(과)`, `(와)`, `.을`, `.를` 같은 잘못된 결합이 없는지 검사한다.

### 실제 브라우저 검사

- 320×720, 375×812, 768×1024, 1280×800에서 확인한다.
- 임무 1과 임무 3을 각각 처음부터 결과 비교까지 완주한다.
- 모바일에서 현재 부품군 선택지 외의 선택지가 한꺼번에 보이지 않는지 확인한다.
- 시험 버튼이 네 번째 부품 선택 단계 전에는 보이지 않는지 확인한다.
- 조건 카드의 남은 개수와 실제 확인 개수가 일치하는지 확인한다.
- 결과와 비교 문장을 소리 내어 읽었을 때 어색한 조사가 없는지 확인한다.
- 브라우저 콘솔 오류와 가로 넘침이 없는지 확인한다.

## 10. 완료 기준

다음 조건을 모두 만족하면 v0.3.0 개선을 완료한 것으로 본다.

1. 초등 3~4학년용 쉬운 말 계약이 모든 학생 화면에 적용된다.
2. 첫 설계는 4단계 부품 선택으로 진행된다.
3. 모바일에서 시험 버튼이 선택지보다 먼저 나오지 않는다.
4. 결과 카드와 비교 문장에 조사·문장 결합 오류가 없다.
5. 기존 조건 판정과 한 부품 변경 규칙이 유지된다.
