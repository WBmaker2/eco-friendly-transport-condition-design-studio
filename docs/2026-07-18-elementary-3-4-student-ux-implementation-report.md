# 친환경 수송 조건 설계소 초등 3~4학년 개선 구현 보고서

- 구현일: 2026-07-18
- 대상 버전: v0.3.0
- 대상 사용자: 초등 3~4학년 학생
- 기준 설계: `docs/superpowers/specs/2026-07-18-elementary-3-4-student-ux-design.md`

## 1. 개선 목표

학생이 교사의 추가 설명 없이도 다음 행동을 찾고, 한 번에 한 종류의 부품에 집중하며, 첫 수레와 바꾼 수레의 결과를 쉬운 문장으로 비교하게 한다. 기존 조건 판정 수치와 한 부품만 바꾸는 규칙은 유지했다.

## 2. 개선 전 실사용 문제

375×812 모바일 화면에서 학생 흐름을 직접 완주해 다음 문제를 확인했다.

1. `시제품`, `의뢰`, `재설계`, `적재부`, `접지`, `조향`, `제동`, `환경 프로필` 같은 낱말이 3~4학년에게 어려웠다.
2. 부품 선택지 12개가 한 화면에 이어져 현재 해야 할 일이 잘 보이지 않았다.
3. 아직 누를 수 없는 시험 버튼이 선택지보다 먼저 나타났다.
4. 조건 카드를 누르는 행동과 `펼쳐야 한다`는 안내가 맞지 않았다.
5. `보조을(를)`, `바퀴과`, `조향과(와)`, `있어요.을`처럼 조사가 어색한 문장이 있었다.
6. 결과에서 어떤 부품을 살펴봤는지와 왜 그런 결과인지 빠르게 연결하기 어려웠다.

기존 화면 증거는 `.gstack/design-reports/screenshots/2026-07-18-student-*.png`에 보관했다.

## 3. 구현 내용

### 쉬운 말

- 진행 단계를 `할 일 → 조건 보기 → 수레 만들기 → 첫 시험 → 다시 만들기 → 결과 비교`로 바꿨다.
- 부품군 이름을 `짐받이`, `바퀴`, `움직이는 힘`, `방향·멈춤`으로 통일했다.
- 학생 화면의 `시제품`, `수송 의뢰`, `재설계`, `비교서`, `환경 프로필`을 구체적인 일상 표현으로 바꿨다.
- `적재함`, `자체 무게`, `제어에는 제한`처럼 실사용 중 추가로 발견한 표현도 쉬운 문장으로 고쳤다.
- 조사가 필요한 긴 자동 문장 대신 `바꾼 부품`, `더 좋아진 조건`, `하지만 생각할 점`을 짧은 문장으로 나눴다.

### 4단계 첫 수레 만들기

- `짐받이 → 바퀴 → 움직이는 힘 → 방향·멈춤` 순서로 한 종류씩 고르게 했다.
- 각 단계에는 해당 부품의 선택지 3개만 표시한다.
- 현재 단계, 완료한 단계, 남은 단계를 글자와 숫자로 함께 보여 준다.
- 선택하지 않으면 다음 버튼이 비활성화되고 해야 할 행동을 짧게 안내한다.
- 시험 버튼은 네 번째 단계에서만 나타난다.
- 모바일은 선택지, 수레 그림, 이동 버튼 순서로 읽히게 했다.

### 한 부품 다시 만들기

- 먼저 바꿀 부품군 하나를 고르게 했다.
- 선택한 부품군의 선택지 3개만 표시한다.
- 나머지 세 부품은 `그대로 두는 부품`으로 요약한다.
- 부품군을 바꾸면 이전의 임시 변경을 지워 두 부품이 함께 바뀌는 일을 막는다.
- 첫 수레와 정확히 한 부품만 다를 때 시험 버튼을 사용할 수 있다.

### 결과 이해

- 상태를 `잘 맞아요`, `조금 아쉬워요`, `다시 골라 봐요`로 줄였다.
- 결과 카드에 `살펴본 부품`, `왜 그런가요?`, `생각할 점`을 함께 표시한다.
- 에너지 설명은 `움직일 때`, `힘을 마련할 때`, `만들고 버릴 때`로 나눴다.
- 비교 화면은 `더 좋아진 조건`, `그대로인 조건`, `새로 생각할 점`으로 정리했다.

### 업데이트 내역

- 최신 항목으로 `2026-07-18 · v0.3.0`을 추가했다.
- 쉬운 말, 4단계 부품 선택, 결과 설명 개선을 학생도 읽을 수 있는 문장으로 기록했다.

## 4. 코드 구조

- `app/transport/student-copy.ts`: 학생용 진행 단계, 상태, 부품 이름, 비교 문장 규칙
- `app/transport/build-steps.ts`: 4단계 순서와 이동 규칙
- `app/transport/BuildStep.tsx`: 첫 수레 단계형 부품 선택
- `app/transport/RedesignStep.tsx`: 한 부품 다시 만들기
- `app/transport/ResultBoard.tsx`: 조건 결과와 에너지·환경 설명
- `app/TransportApp.tsx`: 전체 단계와 상태 연결
- `tests/student-copy.test.ts`: 어려운 말과 조사 오류 회귀 검사
- `tests/build-steps.test.ts`: 선택 순서와 다음 단계 규칙 검사

모든 코드 파일은 500줄 미만이다. 부품 ID, 조건 수치, 평가 방식은 바꾸지 않았다.

## 5. 테스트 주도 구현 기록

1. 새 문장·단계 모듈을 만들기 전 테스트를 실행해 모듈 없음 실패를 확인했다.
2. 결과 설명의 괄호 조사 테스트를 추가해 실제 실패 문장을 확인했다.
3. 쉬운 말 규칙과 단계 로직을 구현한 뒤 집중 테스트 7개를 통과시켰다.
4. 실사용 중 남은 `적재함`, `자체 무게`, `제어에는 제한`을 금지 목록에 추가해 실패를 확인한 뒤 문장을 수정했다.
5. 전체 단위 테스트, 타입 검사, 린트, 프로덕션 빌드를 최종 관문으로 사용했다.

## 6. 실제 학생 흐름 점검

### 완주한 할 일

- 할 일 1 `가까운 교실 준비물`: 첫 화면부터 조건 확인, 부품 4개 선택, 첫 시험, 한 부품 변경, 결과 비교까지 완주
- 할 일 3 `학교 텃밭 묘목 옮기기`: 같은 전체 흐름 완주

### 확인 결과

- 현재 부품군의 선택지 3개만 표시됨
- 첫 세 단계에서 시험 버튼 0개, 네 번째 단계에서 시험 버튼 1개
- 다시 만들기에서 선택지 3개와 그대로 두는 부품 3개 표시
- 조건 5개를 누른 뒤에만 부품 선택 버튼 활성화
- 결과 카드 5개에 상태, 근거 부품, 까닭, 생각할 점 표시
- 조사 오류 탐지 결과 없음
- 브라우저 콘솔 오류 없음

### 반응형

| 요청 화면 | 실제 내용 너비 | 가로 넘침 |
|---|---:|---|
| 320×720 | 305px | 없음 |
| 375×812 | 360px | 없음 |
| 768×1024 | 753px | 없음 |
| 1280×800 | 1265px | 없음 |

브라우저의 세로 스크롤바 너비를 제외한 실제 내용 너비를 기준으로 확인했다.

## 7. 디자인 비교

| 항목 | 개선 전 | 개선 후 |
|---|---|---|
| 선택 밀도 | 부품 12개가 한 화면에 이어짐 | 현재 단계의 부품 3개만 표시 |
| 다음 행동 | 비활성 시험 버튼이 먼저 보임 | 선택 뒤 `다음 부품`, 마지막에만 시험 |
| 부품 이름 | 구조·적재부, 이동부 등 | 짐받이, 바퀴 등 |
| 결과 설명 | 긴 문장과 괄호 조사 | 살펴본 부품·까닭·생각할 점 |
| 다시 만들기 | 여러 부품군 선택지가 이어짐 | 바꿀 곳 선택 뒤 3개만 표시 |

새 화면은 기존의 차분한 종이색, 초록색, 둥근 카드 디자인을 유지하면서 학습 순서와 정보 밀도만 개선했다.
